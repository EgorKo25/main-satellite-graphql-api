# Контекст ревью для продолжения разработки

Этот документ можно передать агенту на другом компьютере вместе с репозиторием. Он фиксирует итоговые решения ревью на 08.10.2026. Полные правила Go, PR, SemVer и glab находятся в [AGENTS.md](AGENTS.md); установка локальных skills не нужна. При расхождении с более новым указанием пользователя действует новое указание. Основной [README.md](README.md) предназначен для запуска и проверки проекта, этот файл — для разработки.

## Что понять до изменения кода

Пользователю нужен небольшой понятный Go-сервис. Большое количество слоёв, преобразователей и универсальных типов не компенсируется красивыми названиями паттернов. Операция должна читаться целиком: проверка входа, транзакция, блокировка, запись, commit и обработка ошибок. Небольшое повторение допустимо, если извлечение хелпера скрывает эту последовательность.

Если пользователь разбирает файл и задаёт вопросы, сначала обсуждай и собирай замечания. Не начинай параллельную переработку архитектуры. Показывай один сквозной сценарий, например изменение Chair, и объясняй, какие структуры действительно нужны. Не выдавай новую схему слоёв за выполненную реализацию.

Работай небольшими законченными изменениями. Проверяй Git до начала, сохраняй пользовательский код. Не создавай несколько PR с разными версиями одного решения. PR #2–#6 были заменены PR #1. Последнее поручение — сохранить эти правила и слить PR #1 merge-коммитом в main. После слияния новые задачи начинаются от актуального main; это поручение не разрешает автоматически сливать будущие PR.

## Стиль Go

- Конструктор находится непосредственно над создаваемой структурой, методы — под ней. Обычный код не требует поясняющих комментариев; директивы генерации и build tags сохраняются.
- Соседние обычные объявления объединяются в `var (...)`. Результат вызова внутри функции объявляется через `:=`, а не переносится в var ради группировки.
- Существующий err переиспользуется: `if err = operation(); err != nil`. Если результата раньше не было и он нужен дальше, обычный `value, err := call()` уместен. Не создавай затенение во вложенном if.
- Не объявляй branch/known заранее только ради объединения вызова и проверки в if. `branch, known := call()` и следующий `if !known` проще, если branch нужен после проверки.
- Хелпер для одного использования не нужен только ради длины функции. Самостоятельная ответственность, повторное использование или callback библиотеки могут оправдывать функцию. Лимит cyclop в этом проекте — 15; не обходи его бессмысленной декомпозицией. Gocritic не подавляется.
- Ошибки оборачиваются по месту через `fmt.Errorf` с `%w`. Sentinel errors остаются для категорий и `errors.Is`; собственный универсальный error-framework не нужен. GraphQL-коды и безопасные сообщения формируются на транспортной границе.
- Сначала ищи решение в стандартной библиотеке, существующих зависимостях и первоисточниках. Не добавляй библиотеку только потому, что она существует; проверь закреплённую версию и цену использования.

## Как использовать lo

`lo` нужен для выразительной операции над данными, а не для максимального количества вызовов библиотеки. `Map` преобразует элементы, `FilterMap` намеренно отбирает и преобразует, `FindKeyBy` находит один ключ без промежуточного списка. Невалидное поле запроса нельзя молча отбросить фильтром.

Для выбора вызываемой операции используется `Switch.CaseF`: выполняется только выбранный callback. В `Case(condition, function())` функция вызывается до выбора ветки. Это особенно важно для записей в БД, выделения объектов и обращения к nullable-входам. Отдельные тесты должны подтверждать отсутствие вызова невыбранной операции.

Сохранение обычного switch допустимо, если lo добавляет много обвязки. Аналогично не нужно заменять `&value` на более длинную запись. В закреплённом lo v1.53.0 функция называется `ToPtr`, а Go 1.26 поддерживает `new(value)`.

В этом проекте удалены лишние `satelliteInput`, `collectSatellite`, `exactlyOne`, общий rollback и `readTx`. Поиск ветки выполняется на месте, проверка patch остаётся отдельной ответственностью. Общая SQL-проекция используется несколькими операциями и не является запрещённым одноразовым хелпером.

## Итоговая архитектура

`main` загружает конфигурацию и создаёт основные зависимости. `server.Server` отвечает за HTTP-сервер, маршруты и таймауты. GraphQL-резолверы выбирают операцию и вызывают один `postgres.DB`, владеющий пулом. Транзакции полностью находятся внутри DB.Create/Update/Delete; наружу pgx.Tx не возвращается.

Домен содержит Main и конкретные Tool/Table/Chair со встроенными общими полями Satellite. ChairType принадлежит только Chair. Выходы gqlgen напрямую связаны с доменом. Входы сателлитов декодируются gqlgen в maps; отдельный service и копии DTO не нужны.

Squirrel строит INSERT/UPDATE через SetMap. Единственное соответствие вида и таблицы — tool/tools, table/tables, chair/chairs. SDL ограничивает клиентские поля; произвольные JSON maps не являются отдельным публичным API DB. Значения параметризованы, служебные поля добавляются в копию входной map. Не создавай новый ORM или реестр всех полей поверх схемы GraphQL.

Чтение использует SQL-колонки и pgx collector по именам. Общая внутренняя проекция содержит метаданные, одно описание и nullable chair_type. Один `lo.Switch.CaseF` создаёт конкретный доменный объект. List читает страницу и выбранный сателлит через LATERAL UNION ALL одной SQL-командой. Create/update используют RETURNING выбранной таблицы. JSON-декодера в рабочем пути чтения нет; JSON-варианты сохранены в сравнительных тестах.

Update/delete сначала блокируют Main через SELECT FOR UPDATE и проверяют его состояние после блокировки. В Create дополнительная блокировка ещё не существующей записи не нужна. Один `time.Now().UTC()` задаёт время операции, для update/delete — после блокировки. Успех возвращается после commit. Rollback остаётся видимым в defer операции, ошибка логируется кроме pgx.ErrTxClosed.

Миграция 00002 обеспечивает ровно одного сателлита, обе ссылки и одинаковый deleted_at отложенными constraint triggers. Не возвращай удалённые подсчёты сателлитов в Go. Проверки входа, patch, состояния удаления, RowsAffected и ошибок SQL/commit остаются. Новые гарантии БД вводятся новой миграцией, опубликованная история не переписывается.

## Что нельзя потерять при упрощении

- Одно бизнес-поле Query, одно Mutation; сателлиты доступны только через Main. Публичный SDL и написание `update_at` сохраняются.
- OneOf считает переданные ключи, в том числе null. Корректная ветка плюс другая null-ветка — ошибка. Проверяются literals и variables до изменений БД.
- Patch различает отсутствие, null и значение: Omittable для Main, наличие ключа для map. Типизированный nil после gqlgen тоже учитывается. Null очищает описание, но запрещён для title/type/satellite; пустые строки разрешены.
- Пустой update и пустой patch отклоняются. Chair.type меняется abc/cde, разновидность Tool/Table/Chair не меняется. Удаляются обе строки через метку, повторное удаление — ошибка, восстановления нет.
- ID — положительный BIGINT и строка в ответе. Максимальный BIGINT не должен проходить через float64. Проверки формата принадлежат GraphQL-границе, состояние проверяется в DB.
- gqlparser выбранной версии требует дополнительных проверок variables: OneOf, регистр enum, неизвестные поля. Невалидные variables должны остановить даже первый корректный mutation alias. Не удаляй защиту без тестов новой версии библиотеки.

Validator используется для подходящих тегов и создаётся один раз на конфигурацию правил. `required` для строки не эквивалентен запрету null при разрешённой пустой строке. `oneof=abc cde` не реализует GraphQL @oneOf. Reflection/рекурсия требуют измерения, а не автоматического отказа от библиотеки.

Проверка JSON сама по себе не заменяет GraphQL: значения могут быть в variables и прямо в query. Easyjson — декодер, не валидатор схемы. Его общий Interface возвращает числа как float64: в выполненной пробе 9223372036854775807 округлился до 9223372036854775808. Gqlgen сохраняет json.Number. Скорость декодирования типизированного сателлита не доказывает преимущество собственного HTTP-транспорта.

## Конфигурация и запуск

YAML загружается через afero.Fs, созданную в main. Config — объект, не глобальная переменная. App встраивает типизированные Database/HTTP/Logger с вложенными YAML-секциями. Defaults заданы тегами creasty/defaults до Decode; KnownFields и validator проверяют результат. Явные нули не заменяются повторно defaults. URL, пользователь и пароль находятся в YAML, env overrides приложения нет.

Логгер глобальный по отдельному решению пользователя: zap, несколько настраиваемых cores, logger.Get(name), общая FS для файлов. Не распространяй это исключение на остальные зависимости. MemMapFs позволяет проверять файловые выходы; ошибки Write/Sync/Close вводятся через тестовые FS/File.

Main не содержит run-обёртки и обработчиков сигналов. Ошибка конфигурации вызывает panic; ошибка подключения/Serve — log.Error и return с кодом 0. Defer database.Close ставится сразу после успешного создания, закрытие логгера — сразу после получения; ошибка его Close игнорируется. Отмена контекста Server.Serve поддерживает graceful shutdown, но main передаёт Background. Это ограничения текущего проекта, не универсальные рекомендации для любого сервиса.

## Тесты и генерация

Однотипные сценарии оформляй таблицами с общими setup/action/assertions. Разные сценарии не нужно превращать в таблицу callback-ов и флагов. Используй testify/require; не изобретай if+t.Fatal и обёртки assertions. Для частичной структуры — cmp.Diff с явными IgnoreFields либо сравнение нужной части. В goroutines возвращай результат и проверяй его в тестовом потоке.

Моки нужны на границах потребителей, SQL-семантика проверяется настоящим PostgreSQL. Рабочая директива mockgen находится над интерфейсом; генераторы закреплены. Не добавляй функции или exports в production только ради тестов, даже за integration tag. Сгенерированный код не редактируется вручную.

Dockertest запускает контейнер на пакет и отдельную БД с goose-миграциями на тест. Fixtures и тесты лежат вместе в integration_tests. Docker недоступен — ошибка, не skip. Проверяй фактическое состояние БД, rollback второй записи, commit failures, конкурентные удаления и update/delete race. Не трогай чужие volumes и базы. Config-тесты используют локальные YAML-fixtures в MemMapFs, включая смешанные defaults и негативные сценарии.

Перед передачей кода выполняются форматирование, генерация без diff, build, vet, golangci-lint v2, unit/integration и race при поддержке среды. Пропущенная проверка не считается успешной; после правок только документации не нужно заново измерять производительность.

## Уроки измерений

Разделяй четыре уровня: выбор фабрики, декодирование готовой страницы, реальный SQL вместе с передачей и сборкой объектов, HTTP под нагрузкой. Сравнивай одинаковые полностью заполненные результаты. Вне таймера остаются Docker, миграции, заполнение, проверки и прогрев. Сохраняй исходные повторы, версии, commit, параметры, ns/op, B/op, allocs/op и benchstat.

Проверяй 100/500 000/1 000 000 Main, страницы 20/100, первую и глубокую, короткие и длинные описания, NULL и пустые строки. Указывай распределение сателлитов, soft delete, tmpfs, прогрев и последовательность клиентов. Race detector нужен для корректности, но не для сравнительного замера времени. Широкие интервалы не скрывай; среднее не называй p95/p99.

На сохранённом Linux-стенде для первой страницы из 100 объектов на миллионе Main: Scan — 0,900 мс, collector — 0,928 мс, row_to_json + easyjson — 1,110 мс. Collector выбран как компромисс ручного маппинга и скорости. Эти числа относятся к историческому сравнению, не к текущему HTTP-сервису. Доказательства и команды находятся в README и docs/benchmarks.

EXPLAIN исследуется на фактическом SQL с ANALYZE, BUFFERS, TIMING OFF, SETTINGS, FORMAT JSON. Название Index Scan не гарантирует точечный поиск: смотри Index Cond, Filter, Rows Removed by Filter, loops, buffers и Heap Fetches. Проверяй custom/generic/auto, кеш pgx и порядок запросов.

В этом проекте nullable OR объединял список и ID. После глубоких страниц общий план отбрасывал почти миллион строк. Раздельные предикаты устранили проблему; после миграции точечный план использовал 8 shared hit blocks и не исполнял две невыбранные ветки сателлитов. Большой OFFSET остался дорогим. Выбор сначала только ID помогал после VACUUM, но мог проигрывать до него — поэтому не внедрён.

Индексы добавляются по плану и измерениям: PK/UNIQUE уже создают их. Покрывающий индекс увеличивает запись и не гарантирует index-only чтение без visibility map. Перенос согласованности в БД тоже имеет цену: измеряй один Go-код с миграцией и без, учитывай работу триггеров, commit и блокировки. Плановые регрессии лучше проверять буферами и свойствами, чем порогом миллисекунд.

## Документация, поставка и безопасность

Основной README содержит проектные решения и доказательства, без переписки, инструкций агенту и рекламных выводов. Исторические эксперименты маркируются отдельно от актуальной реализации. После изменения архитектуры проверяй весь текст на противоречия.

Архив для сдачи не содержит этот документ, AGENTS, skills, Git/IDE/CI, локальную конфигурацию, токены, кэши и временные файлы. Код, тесты, generated-файлы, миграции, примеры, Docker/Make/линтер и техническая документация входят. Рядом хранится SHA-256; проверяются содержимое, ссылки и сборка после распаковки. Уже переданный архив не перезаписывается незаметно.

Не сохраняй реквизиты из переписки в памяти проекта. Разрешение отправить архив конкретному получателю относится только к этой отправке. Не запускай рассылку или уведомления без действующего разрешения.
